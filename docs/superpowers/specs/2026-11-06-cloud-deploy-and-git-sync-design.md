# Дизайн-Спецификация: Автономный 24/7 Облачный Хостинг и Бесшовная Git-Синхронизация

> **Дата создания:** 06.11.2026  
> **Статус:** Утверждён пользователем  
> **Проект:** Lighter & Polymarket Delta-Neutral Hedger (`Lighter-poly`)  
> **Целевая инфраструктура:** Render.com (Free Web Service) + UptimeRobot + GitHub REST API (v3)

---

## 1. Обзор и Цели

### 1.1. Проблема
В периоды отключения электроэнергии (блэкаутов длительностью от 4 часов до нескольких суток) локальный компьютер выключен. В это время бот мониторинга не работает, не отслеживает рыночные цены, не детектирует сквизы и не отправляет критические алерты о ликвидации в Telegram. При этом при закрытии или открытии позиций со смартфона через Telegram журнал сделок (`pnl_and_points_analysis.csv`) и активные связки (`config.json`) должны непрерывно актуализироваться, а при включении ПК — автоматически и без конфликтов загружаться в локальное рабочее окружение.

### 1.2. Цели
1. **24/7 Автономность:** Развернуть бота в бесплатном облачном сервисе (Render.com), обеспечив постоянную работу 15-секундного цикла мониторинга и Telegram-поллинга.
2. **Предотвращение засыпания контейнера:** Реализовать сверхлегкий изолированный HTTP-сервер пинга (`/health`) на порту 8080 для периодического опроса через бесплатный UptimeRobot.
3. **Бесшовная синхронизация данных (Zero Conflict):** Облачный бот при выполнении операций записи (`/o`, `/c`) сразу отправляет коммит с обновленным `pnl_and_points_analysis.csv` и `config.json` в приватный репозиторий GitHub через защищенный GitHub REST API (с Fine-grained PAT).
4. **Удобный Developer Experience на ПК:** Предоставить две безопасные команды:
   - `npm run sync` — скачивание всех свежих строк CSV и конфигов с GitHub без ручной работы с Git (`git pull --rebase --autostash`).
   - `npm run deploy` — автоматический прогон тестов, проверка типов, стягивание свежего CSV и безопасный пуш обновленного кода в GitHub с последующим авто-деплоем на Render.
5. **Строгая безопасность и изоляция (Zero Leakage):** Репозиторий строго приватный, токен GitHub с минимальными правами только на один репозиторий, веб-эндпоинт отдает только `200 OK` (никаких логов/статистики наружу), секреты изолированы в переменных окружения Render.

## 3. Компоненты и Модули

### 3.1. Микро-сервер пинга (`src/services/healthServer.ts`)
* Реализуется с использованием нативного Node.js модуля `node:http` (нулевые сторонние зависимости).
* Слушает `process.env.PORT || 8080`.
* Маршруты:
  - `GET /` или `GET /health` -> HTTP 200, Content-Type: `text/plain`, тело: `OK`.
  - Любые другие пути или методы -> HTTP 404, тело: `Not Found`.
* **Безопасность:**
  - Полный запрет на вывод информации о системе, логов, балансов или содержимого CSV.
  - Закрытые заголовки (`X-Powered-By` отключен).

### 3.2. Сервис синхронизации с GitHub (`src/services/githubSyncService.ts`)
* Работает напрямую через GitHub REST API v3 (эндпоинты `/repos/{owner}/{repo}/contents/{path}`).
* Не требует наличия установленного `git` CLI или папки `.git` внутри контейнера.
* **Переменные окружения:**
  - `GITHUB_PAT`: Fine-grained Personal Access Token.
  - `GITHUB_REPO`: `Swager2k1/Lighter`.
  - `GITHUB_BRANCH`: `main` (по умолчанию).
* **Логика обновления файла (`pushFileUpdate`):**
  1. Выполняет `GET /repos/{owner}/{repo}/contents/{path}?ref={branch}`.
  2. Извлекает текущий `sha` коммита файла.
  3. Кодирует новое содержимое в Base64.
  4. Выполняет `PUT /repos/{owner}/{repo}/contents/{path}` с телом:
     ```json
     {
       "message": "sync: /c TSM close profit +$42.50 [skip ci]",
       "content": "<base64>",
       "sha": "<file_sha>",
       "branch": "main"
     }
     ```
  5. В сообщение коммита добавляется `[skip ci]`, чтобы не триггерить холостые сборки или тесты в CI при обновлении записей CSV.
* **Graceful Degradation:**
  - Если `GITHUB_PAT` не задан в окружении (например, локальная среда), сервис выводит мягкий лог `[GithubSync] Токен не настроен, синхронизация пропущена` и не прерывает работу приложения.

### 3.3. Модификация `positionSyncService.ts` и `config.ts`
* В функцию `appendRowToCsv(csvRow)` добавляется асинхронный вызов `githubSyncService.syncCsvFile()`.
* В функцию `saveHedgeConfig(config)` добавляется асинхронный вызов `githubSyncService.syncConfigFile()`.
* Запись на локальный диск происходит синхронно, а отправка в GitHub — в фоновом промисе с логированием результата, не блокируя ответ пользователю в Telegram.

### 3.4. Автоматизация в `package.json`
Добавляются новые npm-скрипты:
* `"sync"`:
  ```bash
  git pull --rebase --autostash origin main
  ```
  Безопасно забирает свежие строки CSV и изменения конфигурации из GitHub. Если локально были незакоммиченные правки, `--autostash` временно сохраняет их, накатывает коммиты из репозитория и восстанавливает локальные правки без конфликтов.
* `"deploy"`:
  ```bash
  npm run typecheck && npm test && git pull --rebase --autostash origin main && git push origin main
  ```
  Комплексный конвейер деплоя: проверяет компиляцию TypeScript, гоняет тесты, обновляет локальные данные из репозитория и пушит код на GitHub.

### 3.5. Защита от конфликта инстансов Telegram (`DISABLE_POLLING`)
* Если бот запущен на Render, он держит постоянное соединение через Telegram Polling.
* В `src/index.ts` добавляется проверка:
  ```typescript
  if (process.env.DISABLE_POLLING === 'true') {
    console.log('⚠️ Polling отключен флагом DISABLE_POLLING (локальный режим отладки)');
  } else {
    bot.startPolling();
    if (criticalBot.isConfigured()) {
      criticalBot.startPolling(...);
    }
  }
  ```
* В локальном файле `.env` на ПК выставляется `DISABLE_POLLING=true`, а на сервере Render `DISABLE_POLLING` отсутствует (или равен `false`). Это исключает ошибку `Telegram 409 Conflict`.

## 4. Обработка Ошибок и Пограничные Случаи

1. **Сбой сети при обращении к GitHub API:**
   - Если GitHub API временно недоступен (таймаут, лимиты, сетевая ошибка), ошибка перехватывается в `catch`. Бот продолжает непрерывный мониторинг ликвидаций, а локальная копия файла на диске сохраняется. При следующей операции происходит повторная попытка.
2. **Перезапуск контейнера на Render:**
   - Так как коммиты отправляются в GitHub при каждом действии, состояние репозитория всегда актуально. При холодном перезапуске контейнер выкачивает самый свежий коммит с актуальным `config.json` и `pnl_and_points_analysis.csv` и сразу продолжает мониторить нужные позиции.
3. **Одновременные изменения (Race Condition):**
   - Бот на сервере правит только данные (`.csv`, `.json`). Пользователь на ПК правит код (`.ts`). Git автоматически выполняет Fast-Forward слияние без конфликтов.

## 6. План Тестирования
1. **Юнит-тесты для `healthServer.ts`:**
   - Проверка отдачи `200 OK` на `/` и `/health`.
   - Проверка отдачи `404 Not Found` на посторонние пути.
2. **Юнит-тесты для `githubSyncService.ts`:**
   - Мокирование `fetch` для проверки правильности структуры запросов GET/PUT, Base64-кодирования и заголовков `Authorization: Bearer <token>`.
   - Проверка graceful fallback при отсутствии `GITHUB_PAT`.
3. **Интеграционный тест `positionSyncService`:**
   - Проверка, что вызов `appendRowToCsv` инициирует синхронизацию через `githubSyncService`.
4. **Проверка компиляции и всех существующих тестов:**
   - `npm run typecheck` и `npm test`.
